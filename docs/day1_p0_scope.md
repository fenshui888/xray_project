# Day 1 - Goal Packaging and Scope (P0)

## Problem statement
Проект решает задачу бинарной классификации рентген-снимков грудной клетки: `NORMAL` vs `PNEUMONIA`.  
Цель - помочь ускорить предварительный скрининг, чтобы система отмечала подозрительные снимки и снижала нагрузку на врача на первом этапе.  
Текущая проблема: без формализованного baseline трудно понять, дает ли новая версия модели реальное улучшение качества и готова ли она к интеграции.  
Данные уже организованы по классам, есть базовые скрипты EDA и подготовки валидации, но пока нет единого критерия "достаточно хорошо для деплоя".  
Поэтому на P0 фиксируем метрики успеха, ограничения по времени инференса и минимальный набор артефактов для воспроизводимого релиза.  
Результатом этапа должен стать воспроизводимый pipeline, который на одинаковом сплите стабильно показывает целевые значения и сохраняет все артефакты оценки.

## Success metrics (P0)
- `F1-score (PNEUMONIA class)`: >= `0.88` на валидации.
- `ROC-AUC`: >= `0.93` на валидации.
- `Latency`: <= `120 ms` на 1 изображение (CPU inference, batch size = 1).

## Definition of Done (deployment-ready for P0)
Считаем деплой готовым, если одновременно выполнены условия:
- Есть обученная модель и сохраненный артефакт в `models/` с фиксированной конфигурацией запуска.
- Есть воспроизводимый скрипт обучения и оценки (одна команда запуска, фиксированный `seed`).
- На одном и том же validation split достигнуты все 3 целевые метрики (`F1`, `ROC-AUC`, `latency`).
- Сформирован короткий evaluation report в `outputs/` (метрики, confusion matrix, дата/версия запуска).
- Есть smoke-check инференса на нескольких реальных примерах из датасета без падений пайплайна.
